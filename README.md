# pi-nextcloud

Расширение [Pi](https://pi.dev) для доступа к серверу Nextcloud: **заметки**, **календарь**, **задачи** и **контакты**.

Работает поверх официальных API Nextcloud:

| Раздел    | Протокол                                   | Эндпоинт сервера                                  |
|-----------|--------------------------------------------|---------------------------------------------------|
| Заметки   | REST API приложения Notes (v1)             | `/index.php/apps/notes/api/v1/notes`              |
| Календарь | CalDAV (`VEVENT`)                          | `/remote.php/dav/calendars/...`                   |
| Задачи    | CalDAV, компонент `VTODO`                  | `/remote.php/dav/calendars/...`                   |
| Контакты  | CardDAV (vCard 3.0)                        | `/remote.php/dav/addressbooks/...`                |

DAV-эндпоинты обнаруживаются автоматически через `current-user-principal` → `calendar-home-set` / `addressbook-home-set`, поэтому логин (даже e-mail) не обязан совпадать с внутренним именем пользователя DAV.

## Установка

Из папки проекта:

```bash
pi install /path/to/pi-nextcloud
# или для текущего проекта:
pi install -l /path/to/pi-nextcloud
```

Либо для быстрой проверки без установки:

```bash
pi -e /path/to/pi-nextcloud/src/index.ts
```

## Настройка подключения

Любой из вариантов:

1. **Команда `/nextcloud-setup`** в сессии Pi — спросит URL, имя пользователя и пароль приложения, сохранит конфиг в `~/.pi/agent/nextcloud.json` (права 600) и сразу проверит соединение.
2. **Файл конфигурации** `~/.pi/agent/nextcloud.json` (или путь из переменной `NEXTCLOUD_CONFIG`):

   ```json
   {
     "baseUrl": "https://cloud.example.com",
     "username": "user",
     "password": "xxxxx-xxxxx-xxxxx-xxxxx-xxxxx"
   }
   ```

3. **Переменные окружения**: `NEXTCLOUD_URL`, `NEXTCLOUD_USERNAME`, `NEXTCLOUD_APP_PASSWORD`.

> **Пароль**: используйте *пароль приложения* (Настройки → Безопасность → Устройства и сессии → «Создать новый пароль приложения»). Обычный пароль не подойдёт, если включена двухфакторная аутентификация.

Проверка соединения: команда **`/nextcloud-check`** покажет сервер, пользователя, календари и адресные книги.

## Инструменты (для LLM)

**Заметки** (приложение Notes):
- `nc_notes_list` — список с поиском по заголовку/тексту, фильтр по категории, без содержимого по умолчанию
- `nc_notes_get` / `nc_notes_create` / `nc_notes_update` / `nc_notes_delete`

**Календарь** (CalDAV):
- `nc_calendars_list` — календари, цвета, поддержка событий/задач, read-only
- `nc_events_list` — фильтры: календарь, интервал `from`/`to`, поиск; повторяющиеся события помечаются `rrule`
- `nc_events_get` / `nc_events_create` / `nc_events_update` / `nc_events_delete`

**Задачи** (CalDAV `VTODO`, приложение Tasks):
- `nc_tasks_list` — по срокам, скрытые завершённые (`include_completed`), поиск
- `nc_tasks_get` / `nc_tasks_create` / `nc_tasks_update` / `nc_tasks_delete`
- Статусы: `NEEDS-ACTION`, `IN-PROCESS`, `COMPLETED`, `CANCELLED`; приоритет 0–9; процент выполнения; `completed: true/false` ставит/снимает отметку

**Контакты** (CardDAV):
- `nc_addressbooks_list`
- `nc_contacts_list` — поиск по имени, организации, e-mail, телефону
- `nc_contacts_get` / `nc_contacts_create` / `nc_contacts_update` / `nc_contacts_delete`
- Телефоны/e-mail задаются строками `"значение"` или `"метка:значение"` (`cell:+7…`, `work:a@b.c`); при обновлении списки **заменяют** существующие

### Формат дат

- `2025-06-01` — весь день (`VALUE=DATE`)
- `2025-06-01T15:00:00` — «плавающее» локальное время (сервер/клиент трактуют его в своей таймзоне)
- `2025-06-01T15:00:00Z`, `2025-06-01T15:00:00+03:00` — абсолютное время, нормализуется в UTC

Для событий на весь день `end` — **эксклюзивная** дата (правило DTEND в RFC 5545).

## Конкурентные изменения

- Заметки: перед обновлением автоматически берётся свежий `etag` и отправляется `If-Match` в RFC-формате (значение в кавычках — так требует Notes API); при конфликте (HTTP 412) инструмент вернёт ошибку вместо молчаливой перезаписи.
- Календарь/контакты: обновления и удаления отправляют `If-Match` с etag, полученным при чтении. Слабые etag (`W/"…"`), которые Nextcloud раздаёт для контактов, автоматически нормализуются к сильной форме — иначе Sabre/DAV отвечает 412.

## Ограничения текущей версии

- Повторяющиеся события не разворачиваются в экземпляры: список показывает мастер-событие с полем `rrule`; редактирование отдельного экземпляра не поддерживается.
- Не создаются календари и адресные книги (только использование существующих).
- «Плавающие» даты без таймзоны сохраняются как есть — указывайте момент с `Z`/офсетом, чтобы избежать неоднозначности.
- Вложения заметок (Notes API v1.4) не реализованы.

## Разработка

```bash
npm install
npm test        # node --test: 54 теста, включая оффлайн e2e с фейковым сервером DAV/OCS
npx tsc --noEmit
```

Структура:

```
src/
  index.ts    — точка входа: команды /nextcloud-setup, /nextcloud-check, регистрация инструментов
  tools.ts    — определения инструментов pi.registerTool
  client.ts   — HTTP-клиент: Basic auth, OCS, WebDAV-обвязка, обнаружение DAV-эндпоинтов
  notes.ts    — REST API заметок
  caldav.ts   — CalDAV: календари, события, задачи
  carddav.ts  — CardDAV: адресные книги, контакты
  ics.ts      — iCalendar: даты, сборка/правка VEVENT и VTODO
  vcard.ts    — vCard 3.0: сборка/разбор контактов
  mime.ts     — общий MIME-каталожный формат (развёртка строк, экранирование, фолдинг)
  xml.ts      — разбор DAV multistatus и шаблоны запросов
  config.ts   — конфигурация (env + ~/.pi/agent/nextcloud.json)
  errors.ts   — типы ошибок
```
